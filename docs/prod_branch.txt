Production branch — what to drop from Git (optional)

Two different goals:

1) Lean Docker image for production
   The root .dockerignore already excludes LABS/, monitoring/, docs/, tests/,
   compose overrides, and lab helper scripts from the image build. You do not
   need to delete those from Git for a normal prod deploy: docker build never
   copies them into the image.

2) Prod Git branch with fewer files (smaller clone / no lab noise)
   If you really want prod to not contain lab assets in the repository:

   git checkout prod
   git merge dev

   git rm -rf LABS/
   git rm -rf monitoring/
   git rm -rf docs/
   git rm -f docker-compose.monitoring.yml docker-compose.dev.yml
   git rm -f lab2_commands.txt git_logs.txt
   git rm -f scripts/run_lab6_tests.ps1 scripts/run_lab6_tests.sh

   git commit -m "Remove lab and monitoring stack from prod branch"

   Caveat: the next merge from dev will bring those paths back unless you
   resolve conflicts or repeat the removal. Many teams keep one repo and rely
   on .dockerignore plus "prod only runs docker-compose.yml".

Do NOT remove
   app/monitoring/   — Python metrics used by the running FastAPI app (/metrics).
   scripts/seed_db.py — optional but often kept for ops.
